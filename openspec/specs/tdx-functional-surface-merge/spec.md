## Requirements
### Requirement: External tdx surface merge SHALL be capability-led

The system SHALL reconcile external `tdx` project functionality by capability and evidence category instead of overwriting current repository directories.

#### Scenario: Merge inventory classifies external files
- **WHEN** the merge work reviews files from `D:\MyCode3\tdx`
- **THEN** each candidate MUST be classified as current-newer, external-only useful evidence, conflicting status claim, generated/noisy artifact, or sensitive artifact requiring redaction
- **AND** generated bytecode, pytest caches, and giant raw probe dumps MUST NOT be adopted by default

#### Scenario: Current implementation is newer than external source
- **WHEN** a current repository module implements capabilities not present in the external `tdx` copy
- **THEN** the current repository module MUST be preserved
- **AND** the external copy MUST NOT replace it through bulk overwrite

### Requirement: External tdx documentation SHALL reconcile into the single feature registry

The system SHALL use `FUNCTION_TREE.md` as the destination for merged feature status and boundaries after reviewing external `tdx` documentation.

#### Scenario: External document claims are adopted
- **WHEN** an external `tdx` document contains a feature claim that remains true in the current repository
- **THEN** `FUNCTION_TREE.md` MUST either already contain or be updated to contain the corresponding status, evidence, and boundary
- **AND** supporting docs MUST point readers back to `FUNCTION_TREE.md` as the authoritative feature map

#### Scenario: External document claim conflicts with current boundary
- **WHEN** an external `tdx` document describes a capability more broadly than current evidence supports
- **THEN** the registry MUST retain the narrower evidenced boundary
- **AND** the broader claim MUST NOT be represented as currently available

### Requirement: Merge evidence SHALL be curated and reviewable

The system SHALL adopt only curated evidence artifacts or documentation references from the external `tdx` tree.

#### Scenario: Evidence is imported into the repository
- **WHEN** implementation imports validation evidence from `D:\MyCode3\tdx`
- **THEN** the imported artifact MUST be small enough to review
- **AND** it MUST avoid unsanitized account-sensitive material unless explicitly accepted as historical validation evidence

#### Scenario: Evidence remains external
- **WHEN** a useful evidence artifact is too large, noisy, or sensitive to import
- **THEN** repository documentation MAY reference the external path
- **AND** the feature registry MUST distinguish that external reference from checked-in implementation evidence

### Requirement: Merge verification SHALL protect current capabilities

The system SHALL verify that adopting external `tdx` functionality and evidence does not regress current repository capabilities.

#### Scenario: Focused verification runs after merge changes
- **WHEN** implementation changes registry, docs, curated evidence, or tests for this merge
- **THEN** focused verification MUST include the function-tree registry validator and relevant trade or bridge tests
- **AND** failures MUST be resolved or explicitly documented before the change is considered apply-complete

#### Scenario: Full verification is deferred
- **WHEN** full test execution is impractical in the local environment
- **THEN** the implementation result MUST state which focused checks ran
- **AND** it MUST state what residual risk remains

### Requirement: Deferred plugin DLL material SHALL be reconciled as a bounded asset
The system SHALL reconcile the external `docs\TestPluginTCale` material through a separate bounded plugin/DLL asset change rather than by bulk-importing the external docs tree.

#### Scenario: Plugin sample is adopted after the main merge
- **WHEN** the external `D:\MyCode3\tdx\docs\TestPluginTCale` sample is adopted into the current repository
- **THEN** the adoption MUST remain curated and reviewable
- **AND** generated or user-local Visual Studio artifacts MUST be excluded
- **AND** the adoption MUST NOT broaden current runtime formula or trading capability claims
