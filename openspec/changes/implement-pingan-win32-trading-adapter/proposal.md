## Why

`docs/pa-sect-read.md` 定义了一个基于 Win32 消息的后台交易能力，但真实验证已经证明“平安证券当前版本可以通过纯后台 `BM_CLICK/WM_COMMAND` 完成最终提交”这个前提并不成立。同时，通达信线路已经穷举了当前技术栈下合理的 Win32/UIA 级方案，仍然卡在交易业务层对“证券代码输入确认机制”的校验上。现在需要把三件事同时沉淀成工程规格：

- 平安证券线路的真实边界：可探测、可填单、可读状态，但当前版本不能保证纯非物理提交。
- 通达信线路的真实边界：Win32/UIA 级非物理触发已覆盖切股、填单、按钮触发和注册消息切换上下文，但当前版本仍不能让交易业务层接受证券代码输入。
- 新的实施方向：转向 HID 硬件键盘模拟，使用系统认可的真实键盘事件链路处理交易代码输入。

## What Changes

- 新增平安证券 Win32 后台交易适配能力，覆盖主窗口发现、控件树探测、买入页控件定位、后台写入与点击，并明确当前版本的非物理提交边界。
- 新增运行时发现能力，支持从配置和自动探测中解析平安证券客户端可执行文件位置，并兼容 Windows 原生路径与 WSL 映射路径。
- 新增 Win32 低层调试能力，允许按 `hwnd` 直接读取文本、写入文本和触发按钮，作为券商差异排查工具。
- 新增通达信验证分支，基于真实控件树固化买入页关键句柄映射，并提供一键探测/试填命令。
- 新增 HID 方案设计，定义“硬件键盘模拟 + 现有 Win32 探测/提交流程”的组合闭环，并明确 Windows 主机侧代理、串口/USB 通信协议和安全边界。
- 定义最小可交付闭环：`inspect`、`detect`、`health-check`、`buy` 四类操作的期望行为与失败语义。
- 约束实现方式为“先探测、再识别、后执行”，避免未经验证直接下单。
- 为后续卖出、撤单、确认弹窗处理和委托结果回读预留适配器抽象，但本次不要求完整实现。

## Capabilities

### New Capabilities
- `pingan-win32-order-entry`: 通过 Win32 窗口消息对平安证券客户端执行后台控件探测、字段填充和买入指令触发。
- `pingan-runtime-discovery`: 发现并验证平安证券客户端运行入口，兼容 Windows 路径和 WSL 映射路径，并将实际安装位置暴露给交易适配层。
- `win32-hwnd-ops`: 通过原生 `hwnd` 对任意 Win32 控件执行只读检查、文本写入和非物理点击。
- `tdx-win32-probe`: 通过通达信真实控件树识别买入页关键控件，并执行非物理试填/试提交流程。
- `hid-keyboard-order-entry`: 通过 HID 硬件键盘模拟生成真实按键事件，驱动通达信交易代码输入并与现有 Win32 探测/提交流程组合。

### Modified Capabilities

- None.

## Impact

- 新增 OpenSpec 规格、设计和任务拆分，作为后续实现的执行依据。
- 预计影响未来 Python 工程骨架、`pywin32` 依赖、CLI 命令以及 Windows 专用适配层。
- 预计新增 Windows 主机侧 HID 代理、串口/USB 通信协议文档、Arduino Leonardo/兼容 HID 板卡固件样例。
- 依赖真实安装路径进行验证：当前确认的 WSL 路径为 `/mnt/d/ProgramData/PinganSec/TdxW.exe`，而不是 `/mnt/D/...`。
- 需要在真实 Windows/WSL 环境中手工验证控件树，因为不同客户端版本可能存在类名、层级或文本差异。
- 当前结论要求文档和 CLI 都显式区分“可填单”与“可纯后台提交”，不能再把二者视为同义。
- 当前结论还要求路线切换：继续在 Win32/UIA 层面深挖的回报率已经极低，后续实现重心应转向 HID 硬件键盘模拟。
